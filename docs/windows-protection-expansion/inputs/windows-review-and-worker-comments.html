The implementation honors audit mode for device admission but still enforces its lifetime restriction. MS-KILE §3.3.5.6 conditions application of nonzero policy TGTLifetime on effective enforcement. Required change: keep configured policy lifetime and effective issued lifetime separate. Align the decision object, ticket, client reply, canonical state and rendered inspector. Do not change the baseline to conceal this discrepancy.

Acceptance: the audit case still records would-deny and accepts authentication, while retaining the ordinary 480-minute limits. Enforced 120-minute and unarmored lifetime-only 90-minute controls remain correct. If zero lifetime is supported, it must preserve the baseline. Add literal expectations for these fields, then check full/field/exact-object replay and rewind. The original oracle omitted the affected lifetime fields: preserve that historical oracle and add an explicitly justified correction layer.

WP-R07 — NTLM proof description puts MIC in the wrong structure

Location: src/windows-remote-administration-lab.js, ntlmProof around line 255, supplied to the shared SMB authoring. The new label is present in 28 of 44 WRA executions; visible exact inspectors reproduce it for local-SAM WRA01/default-filtered and domain-pass-through WRA03/domain-ntlm-explicit in both source and the supplied IIFE.

The symbolic equation places MIC inside blob(timestamp,client-challenge,target-AV,MIC,terminators). The actual transcript MIC is a separate AUTHENTICATE_MESSAGE field. The AV pairs can contain the MsvAvFlags MIC-presence bit, which is not the MIC bytes. The original shared SMB wording already makes that distinction.

Required change: retain the symbolic scope, with unambiguous input naming: HMAC-MD5(ResponseKeyNT, ServerChallenge || NTLMv2_CLIENT_CHALLENGE). Describe the client challenge’s AV pairs and MIC-presence flag separately from the message MIC computation. Name the eight-byte ServerChallenge field rather than interpolating the whole challenge display into the equation. That latter clarification is part of this correction, not a separate finding. No new numerical cryptographic implementation is requested.

Acceptance: corrected source and compiled inspector values for local-SAM and domain pass-through controls; unchanged authentication outcomes and actual message-MIC verification boundary. Authority: MS-NLMP §§3.3.2, 2.2.2.7, 2.2.1.3 and 2.2.2.1.
