## Production modules and integration

- `src/windows-remote-administration-lab.js` implements WRA01-WRA05 using the existing SMB source where applicable. Target-side modeled filter input is explicitly not a usable client token or a native full-token reconstruction. Applied policy belongs to the actual context creation; changing configured policy does not retroactively replace a reused session/token.
- `src/windows-protection-lab.js` implements WPROT01-WPROT05 with the existing Windows logon/SMB sources. Credential Guard and PPL are separate. Selected protected long-term/TGT material does not imply every service-ticket session key is isolated. Authentication-policy facts come from checked armor/PAC evidence, not a caller-supplied device label.
- `src/pam-stack-evaluator.js` and the exact configuration modules implement the pinned Linux-PAM control/phase semantics. `src/pam-foundations-lab.js` supplies PAM01; `src/pam-existing-integration.js` annotates actual existing Linux/SSH operations without mirroring their state namespaces.
- `src/held-object-windows-protection.js` integrates explicit authored inventories. The strict shared held-object compiler is not relaxed. Exact imported scratch holding identities are released at their actual owners; accepted authority and unrelated sessions are retained.
- `src/windows-security-comparisons.js` links real existing mechanisms, including ordinary RDP, Restricted Admin, Kerberos-only Remote Credential Guard and the Protected Users comparison. It creates no duplicate models and transfers no credentials between lessons.
- `src/scenario-search-metadata.js`, the shared picker ranker and `src/app.js` provide hidden discovery metadata and validated case selection. Shared model fields are normalized once, case-only fields retain their own tiers, and prefix checks iterate token Sets without copying them. The static index is prepared before interaction, with its cost included in startup; content signatures still invalidate in-place metadata edits. Matching-case rows reuse DOM nodes by logical scenario ID rather than transient result-object identity. Search metadata does not construct per-keystroke traces or evaluator outcomes.
- `build.mjs` orders these modules for the standalone IIFE. Favicons, the version 1.0/full-name footer, repository link and source-versus-standalone CSP restrictions remain intact.

Compact and expanded modes select their separately authored physical anchors. Expanded Windows owners retain distinct cells and unobstructed local/IPC ports. Protection views draw one physical host hull from the existing participant-parent relationships, including the reserved inventory footprint; they retain authored expanded anchors instead of repacking owners into a generic dock grid. The target-local SAM stays inside its separate target host. An independent geometry regression checks all 50 protection cases for external participants accidentally enclosed by the workstation. External cards and trust-zone bounds use the same 1120x730 coordinate system as their routes; compact participant roles wrap rather than silently truncate. Concise protection-card names preserve the full logical participant name in accessible labels and the real inspector. Actual standalone visual checks verify both corrected host boundaries without renaming protocol owners or changing holdings.

## Visible state and navigation

Case and required comparison controls are before Play. Switching them creates a fresh context and clears playback, field/object traces and inspection. URLs serialize only an allowlisted named case; comparison members reopen at the case default. Unknown, duplicated, empty, encoded-unsafe or unsupported parameters cannot reach an evaluator and produce the safe-base-case notice. Legacy canonical default aliases, including DNSSEC's `unaware-stub`, normalize through declared metadata without inventing another default URL.

Related/comparison activation restores the current visible logical target or persistent Play. Rebuilt library cards retain their own logical focus region. A unique search case is selected directly; ambiguous matches require an explicit case choice and do not silently choose success. Typing/highlighting does not replace a running journey.

PAM shows the exact service file/hash, physical line, C API/flags including 0, hook, raw result, mapped control action, accumulator, next physical row and separate API aggregate/application admission. Pending prefixes do not display future evaluation results. Internal password preliminary/update dispatch is labelled separately from a public API call. Resource limit rows are not PAM control lines. Existing Linux sign-in/elevation and applicable SSH paths link their current configured operation to a fresh foundation fixture. macOS links are explicitly separate Linux comparisons, not claimed macOS configuration.
