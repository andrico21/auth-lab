## MC-R05 - coherent explicit help focus and dismissal

`CompactView.setHelpOpen(open)` updates the shared `heldView.helpOpen`, renders selection and finds the surviving help Close control on open or trigger on close. It focuses that node with `preventScroll` and calls `scrollIntoView({block:'nearest', behavior:'auto'})`. Both trigger/Close activation and Escape use this path. `onKey()` handles help Escape before outer disclosure dismissal and prevents default/stops propagation, so closing help does not close holdings.

This completes the existing nonmodal help lifecycle rather than adding a modal stack. The focus identity machinery restores corresponding help controls through rerenders; normal rendering does not invoke the explicit help scrolling path. Nearest scrolling is limited to deliberate open/Close/Escape, including returning to a trigger that can otherwise be partially clipped. It is not an automatic playback focus or scroll hook. Lifecycle tests cover connected, exposed focus, state/DOM agreement, retained holdings and rerenders/view switches. Deterministic visibility checks are not physical viewport or human AT acceptance.

## MC-R06 - one bounded draft for either modality

`ScenarioPicker` in `src/scenario-picker.js` has one transient `draft` and one promoted `suspended` snapshot containing query text and active result ID, not a search history. Only `StudyController.switchPresentation()` calls `suspend()` on both `scenarioPicker` and `workspacePicker`, promoting either the currently open draft or the last transiently dismissed draft.
