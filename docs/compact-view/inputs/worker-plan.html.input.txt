<main id="worker-plan"><h2 id="assignment-and-completion-criteria">1. Assignment and completion
criteria</h2>
<p>Add a <strong>Compact</strong> presentation optimized for reading and
operating lessons on a phone. Keep <strong>Full</strong>, the existing
diagram/timeline/inspector workspace, available on every device. Both
presentations use the same catalog, scenarios, cases, protocol engine,
object model and current study session. Compact is a presentation
choice, not another protocol workspace or a reduced lesson catalog.</p>
<p>The user has requested a careful implementation plan. This document
defines the worker’s implementation scope; it is not evidence that
implementation or acceptance has happened. Execute the phases below
without stopping for routine design confirmations. A first
implementation is complete when all required functionality exists,
measured results are delivered against exact inputs, failures and
unavailable acceptance checks are disclosed, and an independent review
can reproduce the result. Publication and existing owner acceptance
remain separate.</p>

<h2 id="product-decisions-fixed-by-this-plan">3. Product decisions fixed
by this plan</h2>
<h3 id="view-choice-startup-and-persistence-mc-01">3.1 View choice,
startup and persistence — MC-01</h3>
<p>Use the visible labels <strong>Compact</strong> and
<strong>Full</strong>, grouped under <strong>View</strong>. Implement a
named radio group or correctly labelled mutually exclusive pressed
buttons. It is not a tab bar unless a complete tab interaction model is
deliberately implemented; ordinary buttons/radios are preferred
here.</p>
<p>Resolve the initial mode once, before mounting either
presentation:</p>
<ol type="1">
<li>A valid remembered explicit choice wins.</li>
<li>Otherwise, use Compact at an initial layout viewport width of
<strong>700 CSS px or less</strong>, Full above 700.</li>
<li>If viewport detection is unavailable, use Full; both controls remain
available.</li>
</ol>
<p>Store only a validated <code>compact</code> or <code>full</code>
enum, under a versioned preference key such as
<code>auth-flow-studio.presentation.v1</code>. Catch storage read/write
failures, including file-origin restrictions, and retain a working
page-memory preference. Do not persist automatically suggested mode as
an explicit choice. Do not persist session state, searches, environment
drafts or object values to remember the view. Do not auto-switch on
resize, orientation, zoom, keyboard appearance or another tab’s
preference change.</p>
<p>Mode selection and <strong>Open Full diagram</strong> use the same
switch operation. The latter selects Full at the same study cursor,
without navigating to another lesson. Returning to Compact uses the
normal mode control. Neither action adds a browser-history entry.</p>

<h3 id="configuration-links-and-existing-full-capabilities-mc-04">3.4

existing lesson/session behavior; preserving a live cursor across a view
switch does not promise persistence across page reload.</p>
<h2 id="protocol-and-evidence-requirements-mc-05-to-mc-08">4. Protocol
and evidence requirements — MC-05 to MC-08</h2>
<h3 id="mc-05-current-action-and-result">MC-05: Current action and
result</h3>
<p>The card must distinguish <strong>described action</strong> from
<strong>observed result</strong>. On initial load the first step may be
described, but state remains <strong>Before step 1</strong>. At an
intermediate cursor, receipt, verification, admission or completion
cannot appear early. Use the existing canonical cursor and declared
decision evidence; if an outcome is not recorded at this prefix, say so.
Do not infer a generic “authenticated,” “secure” or “allowed” result
from possession of a credential or successful transport.</p>
<p>Local processing, local IPC, internal exchanges between logical
components and network transfers retain their own labels. A
self-operation is not drawn as a new inter-host transfer. Parent/child
actors retain exact identity even if Full folds them into one visual
card. Long actor/realm/forest names must remain distinguishable.</p>
<h3 id="mc-06-current-holdings-and-history">MC-06: Current holdings and
history</h3>
<p>Use the same owner-local holdings and representation permissions as
Full. Show coverage as complete/partial/not modeled where declared.
Current holdings and cumulative history are separate views; a released
object must not look currently held. Historical inspection does not
grant access to a plaintext representation or a secret held by another
actor. Preserve encrypted/opaque values and permission-scoped readable
fields.</p>
<p>Allow a learner to tap a field definition, follow its path, select an
exact object and inspect its history without a hover interaction or
mandatory switch to Full. The exact object identity, representation,
owner, source event and field occurrence must survive navigation.
Collapsing a long value is acceptable only with access to the complete
permitted value; copy uses exact data, never an ellipsized preview.</p>
<h3 id="mc-07-protocol-specific-detail-remains-available">MC-07:
Protocol-specific detail remains available</h3>
<p>Inventory every current learning/evidence panel and map it to Compact
or a documented Full-only <em>editing/diagram</em> action. Required

projections/components for existing panels over copied renderer
logic.</p>

<h2 id="study-state-and-navigation-contract">5. Study-state and
navigation contract</h2>
<h3 id="one-shared-session-mc-09">5.1 One shared session — MC-09</h3>
<p>There is one session/controller, one scenario context, one held-state
projection and one <code>FlowPlayer</code>. Presentation state is
separate from protocol state. A minimum switch-preservation record
includes:</p>
<ul>
<li>Selected picker/model identity, protocol/Core settings, case,
comparison member, provider profile and runtime environment
draft/applied values plus revision.</li>
<li>Authored snapshot/context identity; source cursor including
milestone/progress; source and visible row indices; initial/selected
flags.</li>
<li>Field/exact-object trace selection, trace queue and mapping, current
actor/object/representation selection and inspection target.</li>
<li>Player queue, queue position, elapsed time, kind, speed,
paused/idle/complete status; current replay scope and chapter.</li>
<li>Existing learning detail, internal-actor preference and custom graph
layouts.</li>
</ul>
<p>Each presentation may separately retain disclosure state, logical
focus and scroll anchors in page memory. Store identities, not DOM
nodes. The presentation enum must not enter the protocol context key or
invalidate model/compiled-state caches.</p>
<h3 id="switch-transaction-mc-10">5.2 Switch transaction — MC-10</h3>
<ol type="1">
<li>Capture logical focus and per-view reading state; pause only if
playing, using <code>FlowPlayer.pause()</code>.</li>
<li>Preserve the exact resulting player/session snapshot. A playing
session becomes paused; an idle/paused/complete session keeps its
status.</li>
<li>Close transient popups and cancel active pointer capture safely.
Preserve logical inspection, trace, unfinished context values and search
text; a view switch is not Apply, Reset or lesson selection.</li>
<li>Unmount outgoing presenter listeners/observers/DOM and stop its
presentation-only scheduling. Mount the destination once.</li>
<li>Render the destination from the same snapshot, without advancing or
re-selecting a step. Restore a valid corresponding control or the mode
control/current-step heading and meaningful scroll anchor. Announce the
view change and paused status once.</li>
<li>A session paused by switching stays paused until explicit Resume; an
already idle/paused/complete session retains its status. Assert all
semantic identities/state/holdings and queue position/elapsed/kind/speed
are unchanged; the permitted playback change is playing→paused.</li>
</ol>
<p><strong>Do not implement switching by calling
<code>selectLabScenario()</code>, <code>refreshConfiguration()</code>,
<code>reset()</code>, <code>selectStep()</code> or
<code>player.stop()</code>.</strong> These current methods clear or
reconstruct session state, discard queues or mark the selected event
complete. Re-selecting the same integer step would incorrectly complete
an in-flight event.</p>
<h3 id="compact-navigation-mc-11">5.3 Compact navigation — MC-11</h3>

boundaries. Full keeps its existing controls and playback semantics. Add
a small shared controller/player primitive for exact queue
position/elapsed inspection and continuation rather than approximating
with fractional seek epsilon values or creating shortened suffix
queues.</p>

success alone does not prove the standalone build.</p>

service workers or weakened CSP to make switching work. Offline
preference and clipboard failures need graceful existing/manual

<h2 id="performance-methodology-mc-19">9. Performance methodology —
MC-19</h2>
<p>Freeze inputs and collection plans before performance runs. The
existing collector
<code>tools/verification/run-next-expansion-performance.mjs</code> uses
1920×1200 and five desktop actions (<code>startup</code>,
<code>idle-filter</code>, <code>selection</code>,
<code>replay-start</code>, <code>playing-filter</code>). Extend/version
it or add a clearly named mobile producer; do not relabel its old
desktop output as phone evidence.</p>
<p>Keep three comparisons distinct:</p>
<ol type="1">
<li><strong>Frozen candidate-07 Full versus new Full</strong> at matched
desktop and representative phone conditions: regression protection.</li>
<li><strong>New Compact versus new Full</strong> on the same
phone/browser/fixture: comparative presentation cost.</li>
<li><strong>New feature actions</strong>—switch, Next/Previous,
disclosure, exact history and large payload—measured as candidate-only
actions with no invented historical baseline.</li>
</ol>
<p>Preserve historical frozen-baseline flags separately from a fresh
candidate-07 control run. A faster Compact result cannot offset a slower
Full cell or waive an inherited startup condition.</p>
<p>Start with seven paired serial samples per comparable cell, alternate
order, isolate browser contexts and do not run acceptance collectors
concurrently with test workers. Predeclare warmup handling and retain it
separately; never delete slow observations after seeing results. Record
raw values, median/range, browser/device/OS, viewport/DPR,
touch/throttle state, storage preference, loading path and
source/test/HTML/producer hashes before/after. Additional samples are
justified by instability or a changed input, not an attempt to select a
favorable subset.</p>
<p>Use the existing descriptive flag rules: increase <strong>over 25%
and over 100 ms for startup</strong>, or <strong>over 25% and over 50 ms
for interactions</strong>. Mark variability when range/median exceeds
25% and absolute range exceeds the corresponding threshold on either
arm. These flags are not statistical significance or owner acceptance.
Every flagged/variable cell requires an explicit disposition.</p>
<p>The startup endpoint must include a usable active view: correct
lesson/cursor, working search/navigation and visible current content
after layout. Do not declare success at an empty shell before lesson
construction. Separate cold startup, action-to-visible-result latency
and resource retention. Use uninstrumented timing runs for comparisons;
graph-call counters, traces and heap diagnostics are separate diagnostic
runs.</p>
<p>For new action responsiveness, predeclare a provisional product
target of <strong>250 ms median / 500 ms maximum</strong> to a usable,
correctly rendered result for mode switching, Next/Previous and ordinary
disclosure opening on the named test device, excluding intentional
playback duration. Large-history/payload actions are measured and
reported separately. Freeze ordinary versus large-history/payload
fixture IDs in phase 0; do not reclassify slow observations after
measurement. These are planning targets, not prior accepted baselines; a
miss requires investigation/disposition, not a fabricated waiver. Record
at least one actual slower-phone task-latency run when available,
otherwise preserve that gap. Emulation or CPU throttling remains
labelled diagnostic evidence.</p>
<p>Structural checks are mandatory regardless of speed: Compact performs
no Full graph/dock/packet rendering, there is one shared player, and
repeated switching does not accumulate active resources. Report source
and standalone byte growth. No claimed speedup substitutes for Full
regression checks.</p>
