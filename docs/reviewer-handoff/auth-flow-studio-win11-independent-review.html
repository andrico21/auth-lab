3. RFC alignment of this change

The reviewed change preserves the relevant Kerberos boundaries. RFC 4120 §3.2.4 permits a server-selected subkey in AP-REP and protects the reply with the ticket session key. §3.2.5 requires client decryption and matching authenticator timestamps before retaining the returned subkey. The candidate keeps those modeled stages and adds only the missing host-local provenance.

RFC 4121 §2 defines the acceptor-subkey preference for subsequent per-message protection when that key is asserted. The selected Windows AES profile already models this distinction; WIN-11 neither changes the early initiator key nor substitutes the acceptor key for AP-REP protection. The RFC permits an acceptor subkey; this report does not claim that every Kerberos exchange must generate one.

MS-KILE §3.1.1.2 supplies the selected Windows AES distinction between AP-REQ and AP-REP subkeys. MS-CSSP §3.1.5 supplies the last-client-token/public-key-binding ordering. The preserved early-binding model is consistent with that timing; the local-origin operation does not move the exchange or credential-disclosure boundary.

Primary RFC text was consulted for this review. The result is a scoped conformance check of the changed educational model and preserved transitions. It is not fresh certification of every existing protocol, a numerical cryptography audit or a live Windows/CredSSP interoperability result.
