UX-01 — P2: journey comparison activation removes its focused trigger without restoring focus
------------------------------------------------------------------------------------------------
Reproduction in the delivered app:
1. Choose Windows NTLMv2 domain authentication (lab-win-ntlmv2-domain).
2. Tab to the related journey button targeting lab-win-negotiate-kerberos, then activate it.
3. The selected scenario changes, but the activated button is replaced. There is no application focus action selecting a surviving control, corresponding replacement, new heading, or Play.
The same destruction occurs when reactivating the ready-made journey button in this Windows family.

Source evidence:
- src/app.js:293-297 delegates related-button activation directly to selectLabScenario.
- src/app.js:415-427 selects the new model and refreshes configuration, with no general focus capture/recovery.
- src/app.js:1034-1038 resets state and calls renderAll.
- src/app.js:497-498 replaces every related-journey button using innerHTML.
- src/app.js:458 likewise replaces every ready-made journey button.
- In contrast, catalog-card rendering explicitly captures/restores focus at src/app.js:475-480. The affected navigation surfaces have no equivalent recovery.

Independent probe: ux-evidence/navigation-focus-probe.mjs. Run from the review workspace with:
  node implementation-review/expansion1/ux-evidence/navigation-focus-probe.mjs
Result: ux-evidence/navigation-focus-result.json. For both paths, the previously focused trigger is detached, the handler completes, and there are zero subsequent focus calls. Related comparison changes the model from lab-win-ntlmv2-domain to lab-win-negotiate-kerberos.

Evidence boundary: this probe uses the supplied DOM harness with explicit focus tracking, following the project's own fixture convention. It proves DOM replacement and missing application focus restoration; it does not emulate native Enter activation, native document.activeElement fallback after removal, or the next native Tab destination. Actual-browser confirmation is still needed. The practical risk is loss of keyboard position/visible focus immediately after a primary learning-navigation action.

Suggested correction: preserve the selected navigation control when possible, or deliberately focus an appropriate persistent destination after scenario change. Add real keyboard activation and live connected/visible activeElement assertions for both ready-made and related-journey controls. The existing native runner enters all 61 lessons through the universal picker (tools/verification/run-expansion-native.mjs:209-210), so its passing all-preset result does not cover this path.

Held-object/replay usability and source boundaries
-------------------------------------------------
The current source separates exact IDs from field aliases and explicitly labels creator, logical holder, representation/store, acquisition cursor, permission-scoped fields, holder observations, and authority. Historical selection cannot gain newly readable fields; related objects are only selectable if currently held by the same logical actor. src/held-object-view.js:338-372.
Owner switching sets the logical owner and opens its complete list; exact inspector selection can remain pinned and is labeled by holder. No owner A-B-A loss was found in the inspected source. The native retained runner explicitly repeats app -> realmA -> app three times in full/compact geometries and compares complete exact holding IDs, then checks live focus through redraw and removal. tools/verification/held-objects-browser-check.mjs:465-508.
Exact replay compiles the artifact-specific history, retaining source indices; the expansion native runner starts connection/field replay through real keyboard controls and compares completed filtered queues against the same full-source canonical prefix. Completion uses the player's seek API rather than waiting through every natural playback. tools/verification/run-expansion-native.mjs:255-290. This is credible prefix/state coverage, not a claim that every scene was watched in natural playback.
Pending/in-flight/receipt and later local acceptance are explicitly distinguished by the inspector and state model. Retained native HC02 checks immediately before/at/after receipt across full/connection/exact replay; deep expansion cases check CredSSP wire receipt versus decoded credentials, NTLM context versus resource authorization, EAP access versus NAS enforcement, SPAKE ticket receipt/validation/cache, and PAKE handoff/receipt/confirmation. No additional mismatch was found in this bounded UX review; semantic/RFC correctness belongs to the separate protocol review.
Reduced motion suppresses the holding acquisition animation (held-object-view.js:331-335); live region changes are tied to authored state, not every animation frame. The focused native report asserts exactly one announcement update across a playing receipt fixture and multiple frames. This does not establish how a real screen reader speaks or whether the lesson is understood.
