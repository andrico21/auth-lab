Auth Lab: implementation needs correction before final acceptance

Review of auth-lab-kerberos-ssh-code(1).zip · package 1.1.0 · approved plan included in the archive

19 confirmed medium-severity corrections; native browser gate still open.

All findings below are P2: specific correctness or usability defects in an educational simulation. They are not claims of exploitable vulnerabilities in a live Keycloak, AD, SSH or SSSD deployment. The review is read-only; application files were left unchanged.

F01 · P2 / MEDIUM

Complete the reciprocal SPNEGO MIC exchange

Source: src/kerberos-ad-lab.js:256-263
Reproduce: lab-kc-kerberos-sso; shared Kerberos bridge variants

Observed. The acceptor sends accept-incomplete + AP-REP without an acceptor mechListMIC. The only MIC is created by the workstation and verified by Keycloak, yet the selected integrity-protected negotiation completes. This is an invalid implementation of the selected even-token exchange, not merely an omitted optional round trip.

Worker change. Give the acceptor and initiator separate MIC instances. Send the acceptor MIC with its final mechanism token; pass it through the browser to local GSS/SSPI for verification before creating the initiator MIC. Model the appropriate negotiation state. If selecting the optional no-MIC branch instead, remove the invented initiator-MIC continuation and label that choice.

Acceptance. Record acceptor create/send → workstation verify → initiator create/send → acceptor verify. A missing or invalid required acceptor MIC stops context completion and downstream application success.

Primary basis: RFC 4178 §5.

F02 · P2 / MEDIUM

Preserve field values within shared ticket instances

Source: src/kerberos-ad-lab.js:157-164
Reproduce: lab-ad-first-sign-in; 13 affected authored models

Observed. At AS creation and reply, Ticket.sname (TGT) and Ticket.realm both equal ticket:tgt:alice:01. Host/service ticket realms similarly become whole-ticket identifiers. Their glossary examples correctly say krbtgt/A.EXAMPLE and A.EXAMPLE. The builder stores one value per object instance, then reuses that value for different field paths. The independent scan found 87 incorrect header operations.

Worker change. Keep creation/provenance metadata at object level and values at field-occurrence level, keyed by instance, field path and representation as appropriate. Shared ticket identity must not imply shared scalar value.

Acceptance. At create/send/use, assert TGT sname=krbtgt/A.EXAMPLE and realm=A.EXAMPLE while the fields still share the same ticket instance. Repeat for host/service tickets and the bridge. Check full-message and focused displays, not only definitions.

Primary basis: RFC 4120 §5.3.

F03 · P2 / MEDIUM

The resulting TGT target also remains krbtgt/A.EXAMPLE. Apply resets playback correctly, but creates a contradictory successful single-realm lesson.

Keep independent hostname/SPN settings distinct. Do not text-patch already issued signed/encrypted material. Withhold unsupported context edits if they cannot be implemented consistently.

Basis: reproduced source/UI contradiction and the approved exact-field, object-ownership or runtime-context contract.

F04 · P2 / MEDIUM

Give the missing-subkey rejection an actual FAST context

Source: src/kerberos-crypto-lab.js:318-321
Reproduce: lab-ad-fast-tgs-missing-subkey

Observed. The request sends only PA-TGS-REQ; no PA-FX-FAST container or definition exists. The KDC then rejects a missing mandatory FAST subkey. A client-local requireFAST flag does not tell the receiving KDC that this is FAST. An ordinary TGS authenticator can omit its subkey.

Worker change. Either stop locally when required implicit armor cannot be constructed, or send an explicitly malformed PA-FX-FAST container alongside PA-TGS-REQ so the KDC is actually processing FAST. Keep the ordinary non-FAST rule distinct.

Acceptance. The failure owner, transmitted container and rejecting check agree. The existing TGT remains usable, no new service credential appears, and an ordinary non-FAST no-subkey comparison is not rejected solely for that omission.

Primary basis: RFC 6113 §5.4.2 · RFC 4120 §3.3.1.

F05 · P2 / MEDIUM

Use the standardized protected FAST error envelope

Source: src/kerberos-crypto-lab.js:198,204,255-259
Reproduce: lab-ad-fast-as-checksum; lab-ad-fast-as-challenge

Observed. The event is called KRB-ERROR, but its PA-FX-FAST occurrences use KDC-REP.padata.PA-FX-FAST. Protected padata contains a generic reason with no PA-FX-ERROR object. Literal Windows error codes can remain profile-gated; this envelope is already specified by the RFC.

Worker change. Use error-specific paths: outer KRB-ERROR.e-data METHOD-DATA → PA-FX-FAST → protected KrbFastResponse.padata → PA-FX-ERROR (137), containing inner KRB-ERROR without e-data. Derive client knowledge from the decoded protected error.

Acceptance. No error occurrence points to a success KDC-REP path. Show inner-error lineage and protected response verification before client failure knowledge. Retain absence of strengthen-key, finished and a new accepted ticket.

Primary basis: RFC 6113 §5.4.4.

F06 · P2 / MEDIUM

Source: src/kerberos-crypto-lab.js:193,268

F07 · P2 / MEDIUM

Make expiry clocks support the selected error

Source: src/kerberos-ad-lab.js:132,209-217
Reproduce: lab-ad-expired-ticket

Observed. The final state has protocolClock=5001, acceptorClock=1000, ticket end=5000, allowed skew=300 and a newly created authenticator time=1000, yet the service returns TKT_EXPIRED. Its displayed server time is before expiration. Even using 5001 is inside the stated expiration skew allowance.

Worker change. Advance effective client/server clocks beyond endtime+skew, for example to 5301, and create a fresh authenticator at that time. Explicitly describe the deliberate attempt with an expired cached ticket. Keep the separate skew/replay fixtures independent.

Acceptance. At rejection, the fresh proof is within server skew and server time exceeds 5300; the original ticket remains the same object. Test the endtime+skew boundary and the next instant, rather than only asserting the authored error string.

Primary basis: RFC 4120 §3.2.3.

F08 · P2 / MEDIUM

Align the stale-key error with its declared reference

Source: src/kerberos-ad-lab.js:52,215,217,230
Reproduce: lab-ad-stale-service-key

Observed. Installed kvno=6 and KDC kvno=7 produce MODIFIED (41), explicitly described as an RFC integrity-failure reference. For this declared RFC condition, an unavailable key version maps to BADKEYVER (44); failed decryption integrity is a different condition. Microsoft profiles can expose MODIFIED here, so code 41 is not universally wrong.

Worker change. Choose a precise RFC condition/error pair, or retain 41 with an explicit authoritative Microsoft-profile basis and accurate attribution. Keep the already-correct issuance → cache → AP delivery → acceptor failure → client error sequence.

Acceptance. Ticket version, installed versions/key identity, detecting check, displayed error and cited profile agree. The service ticket remains cached after rejection and there is no successful AP-REP or service context.

Primary basis: RFC 4120 §3.2.3.

G01 · Complete native acceptance after the corrections

The worker candidly marks this gate blocked. A fresh attempt reached the same missing-browser condition; no native checks ran. Source/harness success cannot close this gate.

The supplied script is useful, but its only F2 test runs Basic Keycloak and its final narrow viewport also retains that scenario. Extend it to the new families before relying on a green result. Exercise dense child-domain forest, PKINIT/FAST and SSH scenes at desktop and narrow sizes, 200%/400% zoom, reduced motion, long context values, expanded internals and focused replay. Check Tab/F2/Escape, nested help, collapse/replay focus restoration, movement, sticky controls, actual text clipping and overlay containment.

Run modular source over HTTP, standalone over HTTP and standalone via file://. Observe actual CSP blocking and attribute violations to the intended directives; a failed file-origin fetch alone can have other causes. Save real screenshots and results with browser/version and exact artifact hash. A second engine is useful if cross-browser support is claimed.

Regression work that will catch these defects

Keep tests grounded in independent protocol and data invariants. Several current negative paths set the desired result directly from a variant while checking good or contradictory values. A test that only asserts the terminal failure will preserve the bug.

  • Assert exact wire field sets, container paths and separate local inputs; compare field occurrence values against the scenario’s actual request/configuration.
  • For negative fixtures, identify the received bad instance, the retained expected input, the comparison and its result. Assert that focused traces reach that same check.
  • Assert ownership before use/send across explicit agent boundaries, fresh identities for new credentials/channels, and source-prefix state without future knowledge.
  • Assert protocol-specific conditions independently: bilateral MIC order, expiry clocks/skew, FAST factor requirements and required OAuth/Device fields.
  • After fixes, rebuild the standalone, rerun the regression/smoke checks, then finish the native gate on the same bytes.
