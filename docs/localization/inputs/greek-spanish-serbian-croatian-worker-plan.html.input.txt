language, not two different languages. Croatian is a separate locale and
requires its own idiomatic text. Provide nine selectable options:</p>

<h2 id="translation-scope-and-integrity">Translation scope and
integrity</h2>
<ol type="1">
<li>Translate the actual human-facing UI, navigation, help,
accessibility text, step descriptions, scenarios, warnings and generated
explanations across <strong>Full and Compact</strong>, using the
existing source-bound system. Include the PNG action and its
status/error messages. The starter translations in this plan are a small
head start; they are <strong>not</strong> complete lesson catalogs.
Finish the translations for all nine options and report actual
unresolved or untranslated entries separately; do not present
schema/binding counts as proof of linguistic accuracy.</li>
<li>Preserve exact protocol names, RFC entities, formal actors, claims,
parameters, identifiers, placeholders, code, URLs and example values.
For example, <code>client_id</code>, <code>nonce</code>,
<code>Realm A</code>, <code>PKINIT</code>, <code>SPAKE2+</code>,
<code>bogus</code> and <code>insecure</code> remain byte-exact where
they are technical names. Translate surrounding human prose, including
generic words such as “protocol”, without changing trust direction,
negation, timing, token state or the distinction between authentication
and authorization.</li>
<li>Use clear professional Greek, Colombian and Spain Spanish, Italian,
European and Brazilian Portuguese, Serbian and Croatian without invented
slang or a claim that a whole country speaks identically. Regional
catalogs may share identical entries where appropriate, but each must
use natural regional grammar and vocabulary where they differ. Croatian
requires its own natural vocabulary and grammar; do not relabel a
Serbian catalog as Croatian. Both Serbian scripts must contain the same
meaning. It is acceptable to derive one script from an authored Serbian
prose catalog through a carefully scoped conversion <strong>if</strong>
it preserves placeholders and protected spans exactly and handles
script-specific spelling/case; apply human-language corrections where
needed. Do not blindly transliterate mixed text, protocol names, URLs or
code. <code>љ</code>/<code>lj</code>, <code>њ</code>/<code>nj</code>,
and <code>џ</code>/<code>dž</code>, letter case and word boundaries need
care. A mechanical conversion is not qualified native-speaker
approval.</li>
<li>Preserve all current languages, translation coverage and behavior.
Make all nine new choices usable offline in the single-file standalone.
Do not add a remote translation API, runtime fetch or externally hosted
font. Retain the existing English recovery path and report unavailable
native-human or assistive-technology review honestly; do not invent such
approval.</li>
</ol>
<h2 id="product-integration">Product integration</h2>
<ul>
<li>Register all nine full tags and labels in
<code>src/localization.js</code> and the existing selection, metadata,
plural, fallback and number-formatting paths. Keep <code>es-CO</code>
distinct from <code>es-ES</code>, <code>pt-PT</code> distinct from
<code>pt-BR</code>, <code>hr</code> distinct from <code>sr</code>, and
both Serbian script tags distinct. Persist and reload the user’s exact
selected region/script. The current application selects exact registered
tags and does not need a new browser-language detection system. If
existing code already receives a bare language tag, use a documented
default without overriding an explicit region or script.</li>
<li>Extend the source-bound catalogs, glossaries,
<code>tools/verification/localization/resources.mjs</code> and the
packed <code>src/localization-resources.js</code> using the current
pipeline. Extend any locale enumerations and plural categories in the
compiler as well as the UI registry. Avoid changing existing catalogs or
duplicating huge derived artifacts beyond what the existing build
actually requires.</li>
<li>The PNG exporter has a <strong>separate eight-message additive
catalog</strong> in <code>src/localization-png.js</code>; add the nine
locales there, preserving its existing source-hash bindings. The
included complete draft PNG messages may be used directly after
contextual checking. Otherwise the new PNG UI can silently fall back to
English even if the main catalogs are complete.</li>
<li>Preserve offline standalone build and language-change behavior:
active playback pauses as the current product does; the selected
scenario/case, step, elapsed position, queue, trace/field selection,
held state and raw search drafts remain intact. The user’s chosen
Serbian script remains selected in both views. Changing language must
not mutate protocol state or implicitly advance a step. Do not change
PNG export behavior beyond translating its UI.</li>
<li>Existing <code>formatCount</code> fallback matches some exact locale
tags; ensure full regional/script tags receive appropriate localized
number formatting when <code>Intl</code> is unavailable. Formatting
human counts is separate from exact protocol values: never reformat an
attribute, example or wire value.</li>
</ul>
<h2 id="plurals-and-search">Plurals and search</h2>
<p>Use the current <a href="https://unicode.org/cldr/charts/49/supplemental/language_plural_rules.html">Unicode
CLDR cardinal rules</a> in both the runtime
<code>Intl.PluralRules</code> path and the supported
no-<code>Intl</code> fallback, and update the compiler’s accepted forms.
Write natural complete messages instead of suffix concatenation. The
fallback must match supported normal numeric inputs and formatting; do
not claim support for CLDR operands or compact-number formats the app
does not actually represent.</p>

</div><p>Numbers above are normal JavaScript numeric inputs; representations
such as <code>1.0</code> may lose visible trailing zeros before
selection. Do not equate Serbian with Russian or English plural rules.
Check the normal and no-<code>Intl</code> paths against the runtime
actually used, including fractional inputs.</p>
<p>The present runtime’s plural capability check and fallback branch on
a base language; make these checks sensitive to the Portuguese region.
Validate observable plural behavior rather than demanding exact
<code>Intl.resolvedOptions().locale</code> text: a conforming runtime
may resolve a regional tag to an inherited parent while still applying
the correct rules.</p>
<p>Add a few useful native search terms per new option for concepts such
as authentication, filtering and validation, alongside existing English
and exact technical searches. Respect NFC/NFD equivalence, Greek case
including <code>σ</code>/<code>ς</code>, and accented Greek text.
Preserve Spanish <code>ñ</code>, Portuguese <code>ç</code>,
<code>ã</code>, <code>õ</code>, Italian accented vowels, Croatian and
Serbian Latin <code>č</code>, <code>ć</code>, <code>š</code>,
<code>ž</code>, <code>đ</code>, and meaningful Greek accents in
displayed/input text and exact matching. A forgiving alias may follow an
exact native spelling, never outrank it; retain exact canonical
identifier/protocol priority. Keep user’s raw input and IME composition
unchanged. Test Serbian in each script, Croatian, Greek, Spanish and
Portuguese region variants, Italian and mixed text containing a
protected name. Do not introduce automatic cross-script rewriting of
technical identifiers.</p>

app/catalogs and ordinary dependency installation. This is a
verification budget, not a deadline for translation work. Reuse the
existing environment, remove only your own transient files when safe,
and report a specific check as unperformed if it cannot fit. No full
suite, performance measurements, browser matrix, repetitive profiling,
giant per-binding reports, forensic copies or new acceptance
process.</p>
<ol type="1">
<li>Use the existing compiler/validation path as needed for the new nine
catalogs and source bindings; report aggregate
missing/stale/invalid/protected-placeholder errors per locale. Run it
only as necessary to compile/validate the change; don’t repeatedly
regenerate or audit all old catalogs if the existing workflow permits a
targeted run.</li>
<li>Exercise all nine selector entries and real translated lesson prose
with a small shared fixture. Check the plural samples above in both
supported paths, natural counts and protected identifiers, native search
and exact-before-alias ordering. Include Portuguese regional plural
differences, Croatian, Serbian both scripts and Greek
<code>σ</code>/<code>ς</code>; use one mixed query with
<code>client_id</code> or <code>PKINIT</code>.</li>
<li>In one available browser, do a short shared smoke covering language
change while paused, both Full and Compact, one script switch,
preservation of state/search input and the localized PNG action/status.
Build the standalone once and confirm it starts offline with the new

scenario matrix; report any unavailable check honestly.</li>
<li>Return one short handoff naming changed files, nine
