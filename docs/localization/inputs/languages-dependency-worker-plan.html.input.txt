</div><p>Record runtime locale support. Treat number formatting separately
from grammatical selection and never change exact protocol
values.</p></li>
<li><p><strong>Devanagari text:</strong> preserve vowel signs, virama,
nukta, joining/shaping and combining marks. The existing search
normalization already preserves Unicode letters, numbers and marks; do
not replace it with ASCII-only matching or strip meaningful marks. See
<a href="https://www.w3.org/TR/deva-lreq/" rel="noopener noreferrer">W3C Devanagari script
resources</a>.</p></li>
<li><p><strong>Malayalam and Bengali text:</strong> preserve each
script’s vowel signs, conjuncts, virama and joiners in displayed text
and raw input; use working offline font fallback and proper shaping.
Test native-script search and composed/decomposed equivalents without
removing meaningful marks. See <a href="https://www.w3.org/TR/beng-lreq/" rel="noopener noreferrer">W3C Bengali script resources</a>
and <a href="https://www.w3.org/International/questions/qa-indic-graphemes.en.html" rel="noopener noreferrer">W3C
guidance on Indic character units</a>.</p></li>
<li><p><strong>Urdu RTL:</strong> use Urdu-specific text and proper
joining, a suitable local/system font fallback and RTL prose. Isolate
exact LTR identifiers and code; do not mirror the protocol graph,
reverse messages or alter byte order. Existing Arabic/Hebrew RTL support
is a base to test, not a substitute for Urdu translation. See the
current <a href="https://www.w3.org/TR/arab-lreq/" rel="noopener noreferrer">W3C Arabic script
resources</a>, which include Urdu; the older Urdu-only W3C draft is
retired.</p></li>
<li><p><strong>Yoruba and Igbo:</strong> preserve dot-below letters,
tone marks and Unicode combining sequences in translations and display.
Existing search creates accent-folded Latin aliases: exact forms must
rank first, and any forgiving alias must remain lower priority because
marks can distinguish words. Test NFC and decomposed equivalents and
collisions such as <code>ọ</code>/<code>o</code>,
<code>ẹ</code>/<code>e</code> and <code>ụ</code>/<code>u</code>. Never
fold canonical technical identifiers or rewrite the user’s raw
input.</p></li>
<li><p><strong>Search:</strong> add a small set of useful
native-language aliases in each of the nine catalogs, including
equivalents of filtering, authentication and validation, while retaining
English queries and exact technical-name priority. Test a real
native-language query for each new language, mixed Hindi or Urdu +
<code>client_id</code>/<code>PKINIT</code>, and an unmatched query.
Preserve raw input, IME composition, case selection and the distinction
between <code>SPAKE2</code> and <code>SPAKE2+</code>.</p></li>
<li><p><strong>Meaning:</strong> preserve negation, conditions, actor
and trust direction, and the distinction between received, verified and
authorized. Pay particular attention to DNSSEC result labels, Windows
token filtering and PAM control flow. Translation may not imply that an
operation has completed before the current step.</p></li>
<li><p><strong>Review status:</strong> record what was translated and
any unresolved/stale/missing entries separately for all nine locales. A
fallback is not a completed translation. Do not claim qualified human or
screen-reader approval unless actually performed; an unavailable human
reviewer does not block completing the implementation and reporting the
limitation.</p></li>
</ul>
