<main id="localization-worker-plan"><h2 id="assignment-and-language-set">1. Assignment and language set</h2>
<p>Implement <strong>Russian, Ukrainian, Hebrew, German, Arabic (UAE),
French and Polish</strong> for the human-facing explanatory layer of
Auth Flow Studio. Retain English as the source of reference and an
always-available language. Support both Full and Compact, including the
offline standalone HTML.</p>
<p>The user’s controlling constraint is: <strong>translate
human-targeted explanations; do not change attribute names, RFC entities
or other technical names.</strong> This plan includes human
navigation/help/accessibility wording needed to use those explanations.
It does not authorize translated protocol models, altered wire examples
or renamed technical entities.</p>
<p><strong>Worker input:
<code>auth-flow-studio-localization-worker-plan.html</code>, document
version 1.</strong> This is a new implementation assignment after the
Compact closure. Complete the engineering work, catalogs and applicable
validation across all seven languages; pilot stages below are
implementation sequencing, not permission checkpoints or substitutes for
the requested scope.</p>

and current <code>he</code> rather than authoring legacy
<code>iw</code>. Region specificity is explicit only where requested.
The tag/registry basis is <a href="#sources">S1–S3</a>. Native names are

<h2 id="exact-translation-boundary">2. Exact translation boundary</h2>
<p>Classify content by meaning and use, not simply by JavaScript
property names. A property called <code>title</code> may be a technical
document title; a string in a state object may be explanatory evidence
that must remain canonical internally.</p>

</div><p>The examples above are <strong>not an exhaustive term list</strong>.
Build a protected-term registry from the actual source, with explicit
occurrence bindings. Preserve capitalization, punctuation, spacing and
Unicode code points of protected fragments. Grammar may move a fragment
within a translated sentence; it may not change the fragment or reverse
the described relationship. Use surrounding words instead of attaching a
translated inflection to an identifier.</p>
<p>Mixed content must be split. For example, the existing PKCE
explanation contains a formula and English teaching text in one code
block. Keep the formula exact; put the explanation in a localized
paragraph or explicit prose segment. Blanket translation and blanket
exclusion of that whole block both fail this assignment.</p>
<p>When classification is genuinely unresolved, keep the English
occurrence intact, record the ambiguity and continue independent work.
An unresolved occurrence is not a completed translation and must appear
in the final coverage report. Do not guess a new technical term merely
to achieve a percentage.</p>

<h2 id="architecture-and-catalog-contract">4. Architecture and catalog
contract</h2>
<p>Use one presentation-only localization service. English models,
cases, protocol engines, the player, state projection and held-object
evidence remain shared. Do not put locale into
<code>protocolConfig()</code>, scenario selection,
<code>runtimeEnvironment.revision</code>, compiled-plan identities,
canonical snapshots or route identities. Do not make
<code>definition()</code> return a translated object that existing
semantic/search code might consume.</p>
<h3 id="inventory-and-stable-references">Inventory and stable
references</h3>
<p>Create an occurrence manifest covering every human-facing string and
generated message branch. Bind each occurrence to a stable semantic
owner, source module/export or renderer, field path,
case/variant/subfixture context, exact English source fingerprint,
classification and protected-parameter contract. Use an external
occurrence registry where canonical records have no stable content ID.
Array offsets or <code>t(englishText)</code> alone are not reliable
identities.</p>
<p>Keep separate counts for unique messages, display occurrences,
generated templates, protected-only occurrences and case/context
branches. Identical English wording in two different semantic contexts
is not automatically the same translation unit. Deduplicate only when
context and parameter contracts agree.</p>
<h3 id="safe-messages-and-parameters">Safe messages and parameters</h3>
<p>Use complete sentences with named typed placeholders, or a small
restricted message tree. Catalogs contain text and approved structural
tokens, not arbitrary HTML, JavaScript, CSS or URLs. Do not introduce a
general-purpose runtime template evaluator or <code>eval</code>.</p>
<p>Suggested namespaces include <code>ui.*</code>,
<code>lesson.&lt;scenarioId&gt;.*</code>,
<code>field.&lt;attributeId&gt;.*</code>,
<code>actor.&lt;id&gt;.*</code>, and
<code>evidence.&lt;ownerId&gt;.*</code>. A generated message
additionally identifies its operation kind and stable occurrence. The
worker may choose equivalent names, but must deliver the mapping and
validation contract.</p>

<h3 id="staleness-fallback-and-completeness">Staleness, fallback and
completeness</h3>
<p>Each translation is bound to the English source fingerprint and its
parameter/term contract. If English meaning or parameters change, mark
the translation stale. Do not keep displaying an old translation merely
because the key still exists.</p>
<p>Runtime fallback is the exact English occurrence, visibly intact and
marked with English language/direction where appropriate. Never fall
back from Ukrainian to Russian or Hebrew to Arabic. The
<code>ar-AE</code> catalog may share build-time Arabic resources, but
must be complete and independently validated for the requested locale. A
malformed stored locale safely resolves to English.</p>
<p>Fallback is resilience, not completion: per locale, report
translated-current, missing, stale, ambiguous, deliberately protected,
author-reviewed and human-reviewed counts separately. Require
<strong>zero missing/stale allowlisted prose and zero protected-token
violations</strong> for engineering completion. English-identical
strings require explicit justification, rather than automatically
counting as translated prose. Development pseudolocales are test tools,
not additional advertised languages.</p>
<h2 id="language-selection-and-state-preserving-switching">5. Language
selection and state-preserving switching</h2>
<p>Put a clearly labelled language selector in the shared shell,
available in Full and Compact. Keep all eight language choices visible
through recognizable native names. Use a native select or an
equivalently accessible control without adding a second custom
interaction system unnecessarily. Always offer a recognizable
<code>English</code> recovery choice.</p>
<p>Initial policy: <strong>a valid explicit saved choice, otherwise
English</strong>. Persist only the chosen allowlisted language tag under
a separate versioned locale preference. Handle denied storage, invalid
data and standalone <code>file:</code> behavior gracefully. Do not
auto-switch on browser-language changes or resize. Existing lesson links
and route serialization stay unchanged; locale-bearing share links are
outside this assignment.</p>
<p>The explicit language-change transaction must:</p>
<ol type="1">
<li>Validate the requested locale; an unchanged selection is a no-op. If
an input is composing text, defer a destructive refresh until
composition commits or cancels; never commit a scenario through an IME
keystroke.</li>
<li>If playing, pause through the existing player path. Capture the
<strong>postpause</strong> cursor and state. This follows the existing
presentation-switch policy; do not automatically resume after changing
language.</li>
<li>Preserve lesson/case/variant/subfixture/profile, chapter, exact
queue object and kind, position/elapsed/speed, protocol clock, runtime
drafts/applied values, selected actor/field/holding/object/connection
history, disclosure/help state and both picker drafts.</li>
<li>Update only the display locale, appropriate
<code>lang</code>/<code>dir</code>, mounted text and locale-sensitive
caches. Do not call setup/selection routines that rebuild a scenario,
reset playback or evaluate a different model. Keep one active
presenter.</li>
<li>Reindex only what needs the new locale. Keep raw query bytes;
restore the active result by stable ID if it still matches. Otherwise
use an explicit nonselecting state. Enter must never activate a stale
invisible result. Cancelled and empty drafts remain
cancelled/empty.</li>
<li>Keep focus on the surviving language control after an explicit
selection. Preserve logical disclosure and reading anchors; translated
text height may change, so semantic position matters more than restoring
a raw pixel offset. Automatic rerenders must not steal focus or
repeatedly scroll.</li>
<li>Announce at most one concise language-change status. Do not replay
all historical observations as fresh live announcements. No new protocol
evidence is produced by a locale change.</li>
</ol>
<p>Where a UI rerender replaces DOM, use stable presentation keys for
restoration. Invalidate chapter, held-inspector, field-index, queue,
detail, PAM, protocol-state and picker-node caches as applicable.
Preserve the MC-R01–07 fixes, including Compact inline definitions, Full
F2, help dismissal, nonempty drafts and 40-field batching.</p>
<h2 id="corpus-coverage-and-translation-quality">6. Corpus coverage and
translation quality</h2>
<p>Translate the complete allowlisted explanatory corpus across all
shipped groups and cases, including success, denial, fallback and
incomplete/not-modeled states. This includes ordinary and advanced
Web/OIDC/SAML/JWT flows; Kerberos/AD DS/forest trusts/PKINIT/FAST;
Windows logon/elevation/filtering/protection; Linux/PAM/sudo and macOS;
SMB/NFS/SSH/network/RADIUS/PAKE; Kubernetes authentication/RBAC; MCP;
DNSSEC; and any other group present in the actual inventory. Inventory
discovery, not this example list, defines completeness.</p>
<p>Include text in hidden disclosures, help panels, attribute
definitions, actor explanations, crypto detail, state/history tables,
credential inventories, representation permissions, coverage gaps,
source qualifications, comparison cards, tooltips, placeholders,
accessible names and live messages. A string is not exempt merely
because the default lesson does not render it.</p>
<p>Create a glossary and short style sheet for each language. Keep
technical names protected, use natural surrounding prose, and choose
consistent words for teaching concepts. Russian and Ukrainian need
independent authoring/review; Polish is not a grammatical variant of
either. Avoid unsupported certainty, dropped negation, softened
requirements and invented explanations.</p>

<h2 id="hebrew-and-arabic-layout-and-exact-technical-content">8. Hebrew
and Arabic: layout and exact technical content</h2>
<p>Set language and direction independently:
<code>lang="he" dir="rtl"</code> and <code>lang="ar-AE" dir="rtl"</code>
for the relevant application root; LTR for the others. For a standalone
document, update document metadata; for a hosted component, do not
change unrelated host-page content. Use HTML direction metadata and
logical CSS spacing/alignment. <a href="#sources">S4–S5</a> describe the
underlying behavior.</p>
<p>Use tightly wrapped directional boundaries for mixed text. A
protected inline name can render as
<code>&lt;bdi dir="ltr" translate="no"&gt;client_id&lt;/bdi&gt;</code>.
Direction for genuinely unknown human input can use
<code>dir="auto"</code>; do not rely on first-character guessing for
known technical values. Apply the markup to complete phrases with
internal punctuation intact. <a href="#sources">S6</a></p>
<p>The following are product requirements, not claims that a standard
mandates this application’s particular graph design:</p>
<ul>
<li><strong>Keep protocol geometry and chronology fixed.</strong> No
global SVG/canvas mirroring, <code>scaleX(-1)</code>, array reversal or
string reversal. Sender, receiver, arrowheads, actor positions, bit/byte
order, queue order and time direction retain their canonical
meaning.</li>
<li>Give code/configuration blocks, raw payloads, URLs, SPNs, DNS names,
hashes and exact technical values an explicit LTR reading context.
Localized explanations inside or beside those regions get their own
prose direction.</li>
<li>Classify tables. Ordinary UI tables may follow the interface
direction; packet layouts, time sequences, sender/receiver comparisons
and technical ordering need explicit fixed-direction containers.
<code>dir="rtl"</code> can change table column flow, so a root attribute
alone is insufficient. <a href="#sources">S5</a></li>
<li>Mirror spatial UI affordances only through an explicit icon policy.
Navigation labels must still unambiguously mean Previous/Next; protocol
arrows never inherit that policy. Do not reverse keyboard commands
globally.</li>
<li>Test punctuation, parentheses, slashes, dots, <code>:</code>,
<code>=</code>, hyphens, negative values, step numbers, adjacent
technical tokens and long unbroken identifiers in real browsers. Logical
copied text must also be correct; a screenshot alone does not establish
byte fidelity.</li>
<li>Use suitable system/local font fallbacks, adequate line height and
wrapping. Avoid uppercase/letter-spacing transformations that damage
Arabic/Hebrew text. Verify Arabic joining and combining marks; do not
insert spaces between letters to fit a card.</li>
<li>Add no translation-only LRM/RLM/isolate/override characters to
canonical strings, copied commands, exports or URLs. Render isolation
with markup. Clipboard actions read canonical raw data, not decorated
<code>innerText</code>.</li>
</ul>
<p>Use a diagnostic view for any suspicious invisible character
introduced into translation catalogs. Reject unexpected bidi control
characters in authored messages unless an exact, reviewed
plain-text-only accessibility need is documented; that exception never
permits modifying raw technical values. Retain meaningful original
Unicode data without silently sanitizing the underlying model.</p>

<h2 id="performance-caching-and-offline-delivery">12. Performance,
caching and offline delivery</h2>
<p>The reviewed standalone is 5,668,235 bytes before localization. Seven
full explanatory catalogs may materially increase size. Measure the
extracted corpus before selecting the packaging strategy and report
per-locale raw/encoded bytes, total HTML bytes, parse/activation cost
and retained memory. Compression ratio alone is not a startup
measurement.</p>
<p>Keep all shipped languages available offline, with no remote
translation APIs, CDN runtime, remote fonts or locale fetch required. A
reasonable starting design is bundled locale resources with only the
selected catalog parsed/indexed on demand; evaluate the actual
fixed-bundler constraints. If changing script layout, explicitly
preserve boot/security tests and CSP. Do not work around a startup
failure by leaving most explanations untranslated or requiring network
access.</p>
<p>Cache English plus the active display resources and only justified
lightweight shared metadata. Bound inactive-locale caches; release
obsolete rendered nodes. Avoid building seven full field indexes or
seven models, especially on first keystroke. New search aliases must not
trigger scenario evaluation.</p>
<p>Predeclare representative Basic, dense protocol, long-text and RTL
fixtures for English startup, saved-locale startup, first/repeated
language changes, first/repeated search, field opening, and both
Full/Compact switch directions. Include source HTTP, emitted HTTP and
standalone file. Measure ready only when the selected-language
explanation and controls are usable, not when an English/empty shell
appears.</p>
<p>Retain the established method where comparable: seven measured
samples per arm/feature, separately retained warmups, alternating paired
order for comparisons, uninstrumented timing and separate diagnostics.
The existing ordinary targets are <strong>250 ms median / 500 ms
maximum</strong>. Existing classification uses a material increase
strictly above 25% <strong>and</strong> above 100 ms for startup or 50
ms for interaction; variation uses range/median strictly above 25%
<strong>and</strong> range above the same absolute bound. Preserve those
definitions for comparable rows; explicitly predeclare any genuinely new
measurement definition before collection.</p>
<p>The immediate localization baseline is the actual frozen
pre-localization candidate. Retain older baselines for their original
comparisons. Do not use faster Compact results to offset Full
regressions or average away one locale’s failure. Record all new flags
and dispositions without an inferred waiver. Test repeated language and
presentation switches for listeners, timers, observers, nodes,
catalog/index retention and qualified heap growth.</p>
<p>The previous 1.7–1.8 second Compact→Full medians remain an open
inherited usability concern. Localization is not permission to ignore or
silently accept them. A new catalog strategy must not erase the old
record or label later measurements as the earlier collection.</p>
